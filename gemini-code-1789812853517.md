## 1. Executive System Overview
Aura Music is a modern, lightweight music streaming application delivering sub-100ms audio playback, ACID-compliant catalog search, non-blocking telemetry activity logging, and personalized annual listening statistics (Aura Unwrapped).

---

## 2. The Four Core ICT Pillars
1. **Hardware & Compute:** Cloud compute running containerized services and Vercel Edge Serverless functions.
2. **Networks & CDNs:** Global CDN edge caching (Cloudflare / Storage CDN) serving audio binaries with sub-100ms latency.
3. **Polyglot Storage:** 
   - Relational PostgreSQL (Supabase) for transactional ACID data (users, metadata, playlists, telemetry).
   - Object Storage (Supabase Storage / S3) for audio binaries (MP3/AAC) and high-res cover art.
4. **Software Services:** Decoupled modular service boundaries (User & Auth, Catalog Search, Streaming Player, Activity Logging & Stats).

---

## 3. Request Lifecycle Architecture
The system operates on two strictly separated operational flows:

### Flow A: Synchronous Audio Streaming Flow (Direct Playback)
- **Path:** Client UI → Streaming Engine → CDN Edge Storage → Audio Buffer
- **Target Latency:** < 100ms time-to-first-byte (TTFB).
- **Behavior:** The client requests the track binary via direct HTTPS stream. Live playback starts immediately as chunks buffer in the browser HTML5 audio element.

### Flow B: Asynchronous Activity Logging Flow (Telemetry)
- **Path:** Client UI (`onEnded`) → Message / API Route → PostgreSQL (`aura_listening_events`) → Batch Stats RPC
- **Behavior:** Completely non-blocking. When a user completes listening to a track, an `EndSong` event payload is dispatched asynchronously in the background. If telemetry fails or network drops, playback is **never** interrupted.

## 4. Governance, Security & Compliance
- **ISO/IEC 27001:2022 ISMS Controls:**
  - **A.5.15 (Access Control):** Strict JWT bearer tokens verifying user identity for all private operations.
  - **A.8.24 (Cryptography):** TLS 1.3 encryption in transit; AES-256 encryption at rest for authentication data.
  - **A.8.15 (Audit Logging):** Audited timestamps on all listening events and playlist mutations.
- **GDPR Data Privacy Mandates:**
  - **Article 25 (Privacy by Design):** Strict database isolation with Row Level Security (RLS).
  - **Article 17 (Right to Erasure):** Automated stored procedure `delete_user_listening_data()` to purge all user telemetry upon request.

## 5. Relational Database Schema (`aura_*`)
All tables use safe additive prefixing (`aura_`) with `CREATE TABLE IF NOT EXISTS` to ensure zero collision with existing database entities.
